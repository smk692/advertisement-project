## ✅ **이미 결정된 정책들**

### **📋 AD_RANK 알고리즘 정책 (확정)**

#### **1. 핵심 공식 및 파라미터**
- **AD_RANK 공식**: `AD_RANK = 최대입찰가 × 클릭전환율(%)`
- **CPC 공식**: `CPC = (바로 아래 상품의 AD_RANK / 본 상품의 클릭 전환율(%)) + 1원`
- **노출 순위 공식**: `노출 순위 = AD_RANK + 노출 기준치 가산점 + 구매 전환 가산점`
- **노출 비중 공식**: `노출 비중 = 상품의 AD_RANK 점수 / 전체 AD_RANK 점수 합계 (30% 상한 제한)`
- **기본 파라미터 설정**:
  - `클릭전환율 계산 기간 = 1주일` (최근 7일 데이터)
  - `방어값 = 0.1%` (클릭전환율 0인 경우)
  - `노출 기준치 = 1,000회` (노출 기준치 가산점 기준)
  - `구매 전환 기준 = 1회` (1,000회 노출 동안 구매 기준)
  - `노출 비중 상한 = 30%` (단일 상품 최대 노출 비중)

#### **2. 전환 추적 정책** ✅ **정책 확정**
- **전환 인정 기준**: 클릭 후 **24시간 내 주문**만 인정
- **기여도 모델**: **Last-Click Attribution** (세션 내 가장 최근 클릭에 기여)
- **매칭 기준**: `mobile_device_id` 기준 매칭
- **중복 배분**: 클릭 수 기준 가중평균 적용
- **주문 취소**: **환불 없음** (클릭 시점에 차감 완료)
- **중복 주문**: **첫 번째 주문만 인정** (24시간 내)

#### **3. 방어로직 정책**
- **데이터 부족 판단 기준**:
  - 클릭전환율 = 0 (클릭수 또는 전환수 부족)
- **방어값 적용 방식**:
  - 클릭전환율 0인 경우 **0.1% 기본값** 사용
  - 방어로직 적용 캠페인은 Redis에 기록
  - 매일 새벽 3시 방어값 통계 업데이트

### **⚡ 시스템 성능 정책 (확정)**

#### **1. 응답 시간 목표**
- **API 응답**: O(1) 조회 1-3ms, 엘라스틱서치 기반 병렬 처리
- **처리량**: 5000 RPS 이상 (병렬 처리로 대폭 향상)
- **클릭 처리**: Worker 50ms 이내 잔액 차감
- **실시간 이벤트**: 예산/잔액 소진 시 즉시 반영
- **배치 처리**: 일반 변경사항 15분마다 반영

#### **2. 데이터 보관 정책**
- **클릭 이력**: 24시간 TTL (`ad_impression_pricings`)
- **실시간 메트릭**: 7일 보관 (`ad_performance_metrics_realtime`)
- **성과 집계**: 5분 윈도우 (Flink Statement)
- **전환 매칭**: 24시간 윈도우 (Flink Statement)
- **AD_RANK 계산**: 1주일 데이터 기반 (클릭전환율 계산)
- **엘라스틱서치 인덱스**: Active + Temp 인덱스 (하이브리드 아키텍처)

#### **3. 예산 모니터링 정책**
- **경고 임계값**: 일일 예산 90% 소진 시 알림
- **자동 중단**: 일일 예산 100% 소진 시 캠페인 자동 중지
- **잔액 알림**: 기본 10,000원 미만 시 알림
- **실시간 처리**: 예산/잔액 소진 시 즉시 랭킹에서 제외
- **자동 재개**: 예산/잔액 충전 시 자동으로 랭킹에 재포함

### **🛡️ 사기 방지 정책 (확정)**

#### **1. 중복 클릭 탐지**
- **탐지 윈도우**: 5분 텀블링 윈도우
- **보상 처리**: Flink 자동 탐지 → compensation-events 발행 → Worker 잔액 복구
- **보상 공식**: `refund_amount = (duplicate_count - 1) × click_price`

#### **2. 품질 관리 기준**
- **필터링 조건**:
  - 잔액 > 0
  - 승인/유효 캠페인
  - 일예산 초과 없음
  - 품절 상품 제외

## 🚨 **정책 결정 필요한 사항**

### **Case 1: 주문 취소 시나리오** ✅ **결정 완료**

**📋 상황 설명:**
```
14:00 - A 유저가 aa 상품 광고 클릭 (광고비 1,000원 차감)
15:00 - A 유저가 aa 상품 주문 완료 (전환 처리)
16:00 - A 유저가 주문 취소 요청
```

**✅ 확정된 정책:**

| 항목 | 결정된 정책 | 비고 |
|------|-------------|------|
| **광고비 환불** | **환불 없음** | 클릭 시점에 차감 완료, 취소와 무관 |
| **성과 지표** | **유지** | CVR/ROAS에서 제거하지 않음 |
| **수익 임팩트** | **플랫폼 유리** | 취소율 5-10%에 따른 수익 보호 |
| **구현 복잡도** | **낮음** | order.cancelled 토픽 불필요 |

**💰 비즈니스 임팩트:**
- **월 예상 취소율**: 5-10% (일반 이커머스 기준)
- **월 광고비 보호**: 취소로 인한 광고비 손실 없음
- **시스템 복잡도**: 단순화 (취소 이벤트 추적 불필요)

---

### **Case 2: 중복 주문 시나리오** ✅ **결정 완료**

**📋 상황 설명:**
```
14:00 - A 유저가 aa 상품 광고 클릭
15:00 - A 유저가 aa 상품 1개 주문 (120,000원)
16:00 - A 유저가 aa 상품 1개 추가 주문 (120,000원)  
17:00 - A 유저가 aa 상품 1개 추가 주문 (120,000원)
총 매출: 360,000원, 클릭 1회
```

**✅ 확정된 정책:**

| 항목 | 결정된 정책 | 비고 |
|------|-------------|------|
| **전환 횟수** | **1번** | 24시간 내 첫 번째 주문만 인정 |
| **기여 매출** | **120,000원** | 첫 번째 주문 금액만 기여 매출로 계산 |
| **CVR 계산** | **1/1 = 100%** | 현실적인 전환율 유지 |
| **ROAS 계산** | **120배** | 정확한 광고 효율성 측정 |
| **광고주 만족도** | **보수적 접근** | 지표 왜곡 방지 우선 |

**💰 비즈니스 임팩트:**
- **성과 지표 정확성**: 현실적 CVR/ROAS로 의사결정 정확성 확보
- **시스템 복잡도**: 단순화 (중복 주문 추적 불필요)
- **광고주 투명성**: 정확한 성과 측정으로 신뢰도 향상
