## ⏰ 배치 테스크 스케줄링

### **배치 테스크별 실행 스케줄**

| 배치 테스크 | 실행 주기 | 실행 시간 | 담당 서버 | 주요 기능 |
|-------------|-----------|-----------|-----------|-----------|
| **AD_RANK 계산 배치** | 캠페인 변경 시 | 즉시 실행 | 배치 서버 | 랭킹 재계산 및 Temp 인덱스 업데이트 |
| **15분 배치 Alias 교체** | 15분마다 | 매시 00, 15, 30, 45분 | 배치 서버 | Elasticsearch Active/Temp 인덱스 교체 |
| **일일집계 배치** | 매일 | 00:00 (자정) | 배치 서버 | daily_spent 초기화, monthly_spent 누적 |
| **일별 요약 배치** | 매일 | 03:00 (새벽 3시) | 배치 서버 | 전일 성과 요약 생성 |
| **카테고리 통계 배치** | 12시간마다 | 06:00, 18:00 | 배치 서버 | 카테고리별 CTR/CVR 통계 재계산 |
| **데이터 정리 배치** | 1시간마다 | 매시 정각 | 배치 서버 | 만료된 데이터 정리, 파티션 관리 |

### **파이프라인 실행 순서**

**AD_RANK 랭킹 업데이트 파이프라인**:
1. 캠페인 변경 이벤트 발생 → AD_RANK 계산 배치 즉시 실행
2. 15분마다 Alias 교체 배치 실행 (Temp → Active 인덱스 교체)

**일일 데이터 처리 파이프라인**:
1. 00:00 → 일일집계 배치 실행
2. 03:00 → 일별 요약 배치 실행 (일일집계 완료 후)

**독립 실행 배치**:
- 카테고리 통계 배치: 06:00, 18:00 독립 실행
- 데이터 정리 배치: 매시 정각 독립 실행

## 🔄 배치 파이프라인별 구현

### **1. AD_RANK 랭킹 업데이트 파이프라인**

**파이프라인 플로우**:
```
캠페인 변경 이벤트 발생
         ↓
   AD_RANK 계산 배치 (즉시 실행)
         ↓
   Temp 인덱스 업데이트
         ↓
   15분 배치 Alias 교체 (15분마다)
         ↓
   Active 인덱스 교체 완료
```

**파이프라인 설명**:
- **트리거**: 캠페인 생성/수정/삭제, 지갑 소진, 일일 한도 초과
- **1단계**: AD_RANK 계산 배치가 랭킹 재계산 후 Temp 인덱스에 업데이트 (즉시 실행)
- **2단계**: 15분마다 실행되는 Alias 교체 배치가 Temp → Active 인덱스 교체
- **결과**: 새로운 랭킹이 Active 인덱스에 반영되어 광고 API에서 조회 가능

#### **✅ AD_RANK 계산 배치**

**처리 로직**:
1. **활성 캠페인 상품 조회**: DB에서 ACTIVE 상태의 캠페인 상품 조회
2. **AD_RANK 계산**: 각 상품별 AD_RANK, CPC, 노출 순위, 노출 비중 계산
3. **Elasticsearch 업데이트**: 계산 결과를 Temp 인덱스에 Bulk 업데이트
4. **에러 처리**: 실패한 항목에 대한 재시도 및 로깅

**체크리스트**:
- [ ] 캠페인 상품 Reader 구현
- [ ] AD_RANK 계산 Processor 구현
- [ ] Elasticsearch Bulk Writer 구현
- [ ] Chunk 기반 처리 설정
- [ ] 에러 처리 및 재시도 로직
- [ ] 성능 모니터링
- [ ] 메모리 사용량 최적화

#### **✅ 15분 배치 Alias 교체**

**처리 로직**:
1. **Temp 인덱스 검증**: 데이터 존재 여부 및 유효성 확인
2. **새 Active 인덱스 생성**: 날짜 기반 인덱스명으로 새 인덱스 생성
3. **Reindex 작업**: Temp → 새 Active 인덱스로 데이터 복사
4. **Alias 교체**: 원자적 Alias 교체 (기존 Active 제거, 새 Active 추가)
5. **이전 인덱스 정리**: 오래된 Active 인덱스들 삭제

**상세 구현 가이드**:

**1단계: Temp 인덱스 검증**
- Elasticsearch의 `_count` API를 사용하여 `ad_rankings_temp` 인덱스에 데이터가 있는지 확인
- 문서 수가 0개이면 Alias 교체를 건너뛰고 로그 기록
- 데이터가 있으면 다음 단계로 진행

**2단계: 새 Active 인덱스 생성**
- 날짜와 타임스탬프를 조합하여 고유한 인덱스명 생성 (예: `ad_rankings_active_20240115_v1705123456789`)
- `ad_rankings_active` 인덱스와 동일한 매핑과 설정으로 새 인덱스 생성
- 인덱스 생성 실패 시 에러 로그 기록하고 프로세스 중단

**3단계: Reindex 작업**
- Elasticsearch의 `_reindex` API를 사용하여 `ad_rankings_temp`에서 새 Active 인덱스로 데이터 복사
- 대용량 데이터의 경우 배치 크기를 조정하여 메모리 사용량 최적화
- Reindex 진행률을 모니터링하고 완료까지 대기

**4단계: 원자적 Alias 교체**
- Elasticsearch의 `_aliases` API를 사용하여 원자적 Alias 교체 수행
- 기존 `ad_rankings` alias를 가진 모든 인덱스에서 alias 제거
- 새 Active 인덱스에 `ad_rankings` alias 추가
- 이 과정은 원자적으로 수행되어 서비스 중단 없이 완료

**5단계: 이전 인덱스 정리**
- `ad_rankings_active_*` 패턴으로 이전 Active 인덱스들 조회
- 새로 생성된 인덱스를 제외한 모든 이전 인덱스 삭제
- 디스크 공간 절약 및 인덱스 관리 최적화

**오토스케일링 안전성**:
- [ ] **배치 전용 서버**: Fargate Spot에서 독립적으로 실행
- [ ] **중복 실행 방지**: Step Functions로 중복 실행 방지
- [ ] **장애 격리**: 배치 실패가 API 서비스에 영향 없도록 설계

**체크리스트**:
- [ ] Step Functions 스케줄링 설정 (15분마다)
- [ ] Temp 인덱스 검증 로직 구현
- [ ] 새 Active 인덱스 생성 로직 구현
- [ ] Reindex 작업 구현
- [ ] 원자적 Alias 교체 구현
- [ ] 이전 인덱스 정리 로직 구현
- [ ] 중복 실행 방지 로직
- [ ] 에러 처리 및 재시도
- [ ] 성능 모니터링

**파이프라인 체크리스트**:
- [ ] 캠페인 변경 이벤트 감지 로직
- [ ] AD_RANK 계산 → Temp 인덱스 업데이트 연동

### **2. 일일 데이터 처리 파이프라인**

**파이프라인 플로우**:
```
매일 자정 (00:00)
         ↓
   일일집계 배치 실행
         ↓
   daily_spent 초기화
   monthly_spent 누적
   자동 충전 실행
         ↓
   매일 새벽 3시 (03:00)
         ↓
   일별 요약 배치 실행
         ↓
   전일 성과 데이터 집계
   일별 요약 생성
   S3 경로 연결
```

**파이프라인 설명**:
- **트리거**: 매일 자정 (00:00) 자동 실행
- **1단계**: 일일집계 배치로 daily_spent 초기화, monthly_spent 누적, 자동 충전
- **2단계**: 3시간 후 일별 요약 배치로 전일 성과 데이터 집계 및 요약 생성
- **결과**: 일일 데이터 정리 완료 및 성과 요약 데이터 생성

#### **✅ 일일집계 배치**

**매일 자정 실행되는 일일집계**:
1. **daily_spent 초기화**: 모든 캠페인의 daily_spent를 0으로 초기화
2. **monthly_spent 누적**: daily_spent를 monthly_spent에 누적
3. **last_spent_date 업데이트**: 최종 사용일 업데이트
4. **자동 충전 실행**: current_balance < alert_threshold인 경우 자동 충전

**상세 구현 가이드**:

**daily_spent 초기화**:
- `ad_balances` 테이블의 모든 레코드에서 daily_spent를 0으로 초기화
- 트랜잭션으로 안전하게 처리하여 중간 실패 시 롤백
- 초기화 완료 후 로그 기록

**monthly_spent 누적**:
- daily_spent 값을 monthly_spent에 누적
- 월이 바뀌는 경우 monthly_spent도 초기화
- 누적 완료 후 로그 기록

**자동 충전 실행**:
- current_balance < alert_threshold인 광고주 조회
- auto_charge_enabled가 true인 경우 자동 충전 실행
- 충전 이력을 `ad_balance_histories`에 기록

**체크리스트**:
- [ ] Step Functions 스케줄링 설정 (매일 자정)
- [ ] daily_spent 초기화 로직 구현
- [ ] monthly_spent 누적 로직 구현
- [ ] 자동 충전 로직 구현
- [ ] 트랜잭션 처리 및 롤백 로직
- [ ] 에러 처리 및 재시도
- [ ] 성능 모니터링

#### **✅ 일별 요약 배치**

**매일 새벽 실행되는 일별 요약**:
1. **전일 성과 데이터 집계**: ad_performance_metrics_realtime 데이터 집계
2. **일별 요약 생성**: ad_event_summaries_daily 테이블에 전일 요약 생성
3. **S3 원시 데이터 경로 연결**: 해당 날짜 S3 원시 데이터 경로 업데이트
4. **데이터 검증**: 생성된 요약 데이터의 무결성 확인

**상세 구현 가이드**:

**전일 성과 데이터 집계**:
- 전일 날짜의 `ad_performance_metrics_realtime` 데이터 조회
- 캠페인별, 상품별, placement별로 집계
- impression_count, click_count, conversion_count, total_spend 계산

**일별 요약 생성**:
- 집계된 데이터를 `ad_event_summaries_daily` 테이블에 INSERT
- unique_users 계산 (중복 제거된 사용자 수)

**S3 원시 데이터 경로 연결**:

**체크리스트**:

## ⚡ 독립 실행 배치

### **✅ 카테고리 통계 배치**

**12시간마다 실행되는 카테고리 통계**:
1. **전체 카테고리 통계 재계산**: ad_category_defense_stats 테이블 업데이트
2. **점진적 평균 업데이트**: 성과 데이터 누적 시 점진적 평균 계산
3. **기간별 계산**: calculation_period 설정에 따라 재계산 (7DAYS/30DAYS/90DAYS)
4. **last_calculated 업데이트**: 마지막 계산 시간 업데이트

**상세 구현 가이드**:

**전체 카테고리 통계 재계산**:
- 모든 카테고리 경로에 대해 CTR/CVR 통계 재계산
- 상위 카테고리 통계를 하위 카테고리에 상속
- 샘플 데이터 개수 확인 및 최소 기준 적용

**점진적 평균 업데이트**:
- 새로운 성과 데이터가 누적될 때마다 평균값 업데이트
- 가중 평균을 사용하여 최신 데이터에 더 높은 가중치 부여
- min_ctr, min_cvr 값도 함께 업데이트

**기간별 계산**:
- 7DAYS: 최근 7일 데이터만 사용
- 30DAYS: 최근 30일 데이터만 사용
- 90DAYS: 최근 90일 데이터만 사용

**체크리스트**:
- [ ] Step Functions 스케줄링 설정 (12시간마다)
- [ ] 카테고리 통계 재계산 로직 구현
- [ ] 점진적 평균 업데이트 로직 구현
- [ ] 기간별 계산 로직 구현
- [ ] 에러 처리 및 재시도
- [ ] 성능 모니터링

### **✅ 데이터 정리 배치**

**정기적으로 실행되는 데이터 정리**:
1. **만료된 노출 가격 정리**: ad_impression_pricings에서 만료된 데이터 삭제
2. **오래된 이벤트 데이터 정리**: ad_performance_metrics_realtime에서 7일 이상 된 데이터 삭제
3. **파티션 관리**: 월별 파티션 자동 생성 및 삭제
4. **아카이브 데이터 관리**: 13개월 이상 된 데이터 아카이브 스토리지로 이관

**상세 구현 가이드**:

**만료된 노출 가격 정리**:
- `ad_impression_pricings` 테이블에서 expires_at < NOW()인 데이터 삭제
- 1시간마다 실행되는 스케줄러로 설정
- 삭제된 데이터 수를 로그에 기록

**오래된 이벤트 데이터 정리**:
