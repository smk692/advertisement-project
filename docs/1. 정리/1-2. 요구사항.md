# AD_RANK 광고 시스템 기획 v3 - 전체 요약 정리

## 1. 개발 배경 및 방향성

**타임라인:**
- 2023.3Q 초: Citrus Ad 오픈소스 도입
- 2025.4Q 목표: 자체 AD_RANK 기반 광고 시스템 구축

**개발 목적:**
- 회사 자체 수수료 구조 개선
- 개발 대기시간 단축
- Citrus Ad의 기본 관리 기능 대체
- **새로운 방향**: 복잡한 RTB에서 정교하고 실용적인 AD_RANK 시스템으로 전환

## 2. 개발 범위 (1차)

**핵심 구성요소:**
- AD_RANK 엔진 (광고 API + Worker + Flink)
- 노출 API
- 어드민 시스템

**요구사항:**
- Citrus Ad와 동일한 구성 및 구현
- 기존 성과 이상의 AD_RANK 엔진 구축
- 확장성: 가격 실험/개인화 대응

## A. 프론트 API 구성

### 광고 영역
- **홈**: 1차 카테고리 기준
- **상품상세**
- **카테고리**: 1~4차까지 지원
- **검색어**: 수동 심사 진행

### Request API
**필수 파라미터:**
- `deviceID`, `sessionID`, `placement`, `searchterm`, `category`, `userID`, `exp_key`, `exp_var`, `maxNumOfAds`

**응답 결과:**
- `[productID, ad_ID]` 배열

### Tracking API (노출/클릭)
**파라미터:**
- `ad_ID`

**호출 시점:**
- **노출시**: AD_RANK에서 각 노출 광고의 정확한 기록
- **클릭시**: 적용가 차감 + 로깅

**사전 매핑 정보:**
- 캠페인ID, 영역, 상품, 입찰가, 적용가

### 구매 트래킹 API
**필수 파라미터:**
- `deviceID`, `sessionID`, `orderDate`, `[productID, quantity, unitPrice, discountedPrice]`

**기여 매출 집계 기준:**
- 클릭 후 24시간 내 주문만 인정
- 세션 내 발생한 가장 최근 클릭 광고에 기여
- 중복 배분 시 클릭 수 기반 가중평균 적용

## C. AD_RANK 엔진 설계

AD_RANK 엔진은 **카테고리별 AD_RANK 계산**, **CPC 계산**, **상품 노출 순위 계산**, **상품별 노출 비중 계산**, **슬롯별 노출 비중 계산**, **랜덤 노출 비중 계산**의 6가지 요소로 구성됩니다.

### 1. 카테고리별 AD_RANK 계산

**목적:** 각 광고 구좌에 카테고리별로 AD_RANK 점수 계산

**AD_RANK 계산 방식:**
- 각 광고 구좌별로 카테고리별 독립적인 AD_RANK 계산
- 동일 카테고리 내에서 광고 간 경쟁
- 카테고리별 독립적인 점수 체계

**실제 계산 예시:**

**카테고리: 노트북**
- **광고 A (삼성)**: AD_RANK = 25점
- **광고 B (LG)**: AD_RANK = 20점
- **광고 C (애플)**: AD_RANK = 15점

**카테고리: 스마트폰**
- **광고 D (삼성)**: AD_RANK = 30점
- **광고 E (애플)**: AD_RANK = 28점

### 2. CPC 계산

**목적:** 정렬된 상품 순서에서 각 상품별 CPC 산정

**CPC 계산 공식:**
```
CPC = (바로 아래 상품의 AD_RANK / 본 상품의 클릭 전환율(%)) + 1원
```

**실제 계산 예시:**

**노트북 카테고리 (AD_RANK 내림차순 정렬):**
1. **광고 A (삼성)**: AD_RANK = 25점, 클릭전환율 = 2.5%
   - **CPC = (20 / 2.5) + 1 = 9원**

2. **광고 B (LG)**: AD_RANK = 20점, 클릭전환율 = 3.0%
   - **CPC = (15 / 3.0) + 1 = 6원**

3. **광고 C (애플)**: AD_RANK = 15점, 클릭전환율 = 2.0%
   - **CPC = 15원** (다음 순위 없음, 최대 입찰가 사용)

### 3. 상품 노출 순위 계산

**목적:** AD_RANK 높은 순으로 기본 정렬 후, 추가 기준으로 최종 노출 순위 결정

**노출 순위 계산 기준:**

#### 3-1. 노출 기준치 충족 여부
- **기준**: 해당 상품의 노출수가 1,000회 이상/이하
- **1,000회 이상**: 가산점 부여
- **1,000회 이하**: 가산점 미부여

#### 3-2. 구매 전환 여부
- **기준**: 해당 상품의 노출 1,000회 동안 구매 1회 이상 여부
- **1회 이상**: 가산점 부여
- **1회 미만**: 가산점 미부여

#### 3-3. 최종 노출 순위 결정
```
최종_노출_순위 = AD_RANK_기본_순위 + 노출_기준치_가산점 + 구매_전환_가산점
```

**실제 적용 예시:**

**기본 AD_RANK 순위:**
1. 광고 A (25점)
2. 광고 B (20점)
3. 광고 C (15점)

**가산점 적용 후:**
- **광고 A**: 25점 + 노출기준치(✓) + 구매전환(✓) = **27점**
- **광고 B**: 20점 + 노출기준치(✗) + 구매전환(✓) = **21점**
- **광고 C**: 15점 + 노출기준치(✓) + 구매전환(✗) = **16점**

**최종 노출 순위:**
1. **광고 A (27점)**
2. **광고 B (21점)**
3. **광고 C (16점)**

### 4. 상품별 노출 비중 계산

**목적:** AD_RANK 점수 기반으로 상품별 노출 비중 계산

**노출 비중 계산 공식:**
```
상품의 노출비중(%) = 상품의 AD_RANK 점수 / 전체 AD_RANK 점수 합계
```

**실제 계산 예시:**

**전체 AD_RANK 점수 합계: 60점**
- **광고 A**: 25점 → **노출비중 = 25/60 = 41.67%**
- **광고 B**: 20점 → **노출비중 = 20/60 = 33.33%**
- **광고 C**: 15점 → **노출비중 = 15/60 = 25.00%**

#### 4-1. 노출 비중 상한 제한

**제한 규칙:**
- 단일 상품의 노출 비중이 30%를 넘는 경우 최대 30%로 제한
- 초과된 비중은 하위 랭크 상품들에 재분배
- 재분배 기준: 각 상품의 원노출 비중 비율

**재분배 예시:**

**원래 노출 비중:**
- 광고 A: 41.67% (30% 초과)
- 광고 B: 33.33%
- 광고 C: 25.00%

**제한 적용 후:**
- 광고 A: **30.00%** (11.67% 초과분 제거)
- 광고 B: 33.33% + (11.67% × 33.33%/(33.33%+25.00%)) = **39.99%**
- 광고 C: 25.00% + (11.67% × 25.00%/(33.33%+25.00%)) = **30.01%**

### 5. 슬롯별 노출 비중 계산

**목적:** 검색어/카테고리별로 1~10번 슬롯별 노출 비중 계산

**슬롯 구성:**
- **1~10번 슬롯**: 현재 최대 10개 슬롯
- **확장 가능**: 추가 슬롯 확장 가능한 구조
- **데이터 기준**: 최근 90일 데이터 기준

**슬롯별 노출 비중 예시:**

**노트북 카테고리 슬롯별 비중:**
- **1번 슬롯**: 30%
- **2번 슬롯**: 23%
- **3번 슬롯**: 19%
- **4번 슬롯**: 14%
- **5번 슬롯**: 9%
- **6번 슬롯**: 5%

### 6. 랜덤 노출 비중 계산

**목적:** 전체 슬롯(1~10번)에 모든 상품 랜덤 노출

**랜덤 노출 옵션:**
- **옵션 1**: 전체 슬롯(1~10번)에 모든 상품 랜덤 노출
- **계산 기준**: 누적 노출수 1,000회 기준으로 데일리 계산
- **목적**: 다양한 노출 전략 제공

**랜덤 노출 비중 예시:**
- **AD_RANK 기준**: 60%
- **랜덤 노출**: 40%

## D. 통합 알고리즘 흐름

### 전체 시스템 흐름

```
STEP 1: 광고 요청 수신
        → 카테고리별 요청 분류
        → 카테고리별 AD_RANK 계산

STEP 2: AD_RANK 내림차순 정렬
        → CPC 계산
        → 상품 노출 순위 계산

STEP 3: 상품별 노출 비중 계산
        → 노출 비중 상한 제한 (30%)
        → 초과분 재분배

STEP 4: 슬롯별 노출 비중 적용
        → 1~10번 슬롯별 비중 계산
        → 최근 90일 데이터 기준

STEP 5: 랜덤 노출 처리
        → 전체 슬롯 랜덤 노출
        → 최종 광고 할당

STEP 6: 광고 노출
        → Tracking API에 impression 이벤트 전송
        → 성과 데이터 수집
```

### 상세 알고리즘 코드

```
// 1단계: 카테고리별 AD_RANK 계산
FOR 각 카테고리별로:
    FOR 각 광고 IN 해당_카테고리_광고들:
        AD_RANK_계산(광고)
    
    // 2단계: AD_RANK 내림차순 정렬
    AD_RANK_순위리스트 = 정렬(해당_카테고리_광고들, AD_RANK_내림차순)
    
    // 3단계: CPC 계산
    FOR i = 1 TO AD_RANK_순위리스트.length:
        IF i < AD_RANK_순위리스트.length:
            CPC[i] = (AD_RANK[i+1] / 클릭전환율[i]) + 1
        ELSE:
            CPC[i] = 최대입찰가[i]
    
    // 4단계: 상품 노출 순위 계산
    FOR 각 광고 IN AD_RANK_순위리스트:
        노출_기준치_가산점 = 노출수 >= 1000 ? 1 : 0
        구매_전환_가산점 = 구매수 >= 1 ? 1 : 0
        최종_점수 = AD_RANK + 노출_기준치_가산점 + 구매_전환_가산점
    
    // 5단계: 상품별 노출 비중 계산
    전체_AD_RANK_합계 = SUM(AD_RANK_순위리스트)
    FOR 각 광고 IN AD_RANK_순위리스트:
        원래_노출비중 = AD_RANK / 전체_AD_RANK_합계
        IF 원래_노출비중 > 30%:
            노출비중 = 30%
            초과분 = 원래_노출비중 - 30%
            하위_상품들에_재분배(초과분)
        ELSE:
            노출비중 = 원래_노출비중
    
    // 6단계: 슬롯별 노출 비중 적용
    슬롯별_노출비중 = 최근_90일_데이터_기준_계산()
    
    // 7단계: 랜덤 노출 처리
    랜덤_노출_비중 = 40%
    AD_RANK_노출_비중 = 60%
```

### 실시간 랭킹 관리 시스템

#### 캠페인 변경 시 랭킹 재갱신

**이벤트 트리거:**
- 캠페인 추가/수정/삭제 시 실시간 이벤트 발생
- 해당 캠페인의 모든 상품 관련 랭킹 재갱신 필요

**재갱신 프로세스:**
```
// 캠페인 변경 이벤트 발생 시
IF 캠페인_변경_이벤트_발생:
    // 1단계: 영향받는 카테고리 식별
    영향받는_카테고리들 = 해당_캠페인_상품들의_카테고리
    
    // 2단계: 각 카테고리별 랭킹 재계산
    FOR 각 카테고리 IN 영향받는_카테고리들:
        // AD_RANK 점수 재계산
        FOR 각 광고 IN 해당_카테고리_광고들:
            IF 광고.캠페인ID == 변경된_캠페인ID:
                AD_RANK_재계산(광고)
        
        // 전체 랭킹 재정렬
        AD_RANK_순위리스트_재정렬(해당_카테고리)
        
        // CPC 재계산
        CPC_재계산(해당_카테고리)
        
        // 노출 순위 재계산
        노출_순위_재계산(해당_카테고리)
        
        // 노출 비중 재계산
        노출_비중_재계산(해당_카테고리)
    
    // 3단계: 캐시 업데이트
    랭킹_캐시_업데이트(영향받는_카테고리들)
```

#### 예산 소진 시 캠페인 일시중지

**예산 모니터링 시스템:**
- 캠페인 지출액 한도 및 거래처 지갑 금액 실시간 추적
- 한도 도달 시 즉시 캠페인 상태 변경

**일시중지 프로세스:**
```
// 실시간 예산 모니터링
WHILE TRUE:
    FOR 각 캠페인 IN 활성_캠페인들:
        // 1단계: 캠페인 지출액 한도 체크
        IF 캠페인.일일_지출액 >= 캠페인.일일_한도:
            캠페인_일시중지(캠페인ID)
            랭킹에서_제외(캠페인ID)
            알림_발송(캠페인_소유자, "예산 한도 도달")
        
        // 2단계: 거래처 지갑 금액 체크
        거래처ID = 캠페인.소유_거래처ID
        IF 거래처.지갑_잔액 <= 0:
            // 해당 거래처의 모든 캠페인 일시중지
            FOR 각 캠페인 IN 거래처.캠페인들:
                캠페인_일시중지(캠페인ID)
                랭킹에서_제외(캠페인ID)
            알림_발송(거래처, "지갑 잔액 소진")
    
    // 3단계: 예산 충전 시 자동 재개
    FOR 각 거래처 IN 일시중지_거래처들:
        IF 거래처.지갑_잔액 > 0:
            FOR 각 캠페인 IN 거래처.일시중지_캠페인들:
                IF 캠페인.일일_지출액 < 캠페인.일일_한도:
                    캠페인_재개(캠페인ID)
                    랭킹에_재포함(캠페인ID)
    
    SLEEP(1분) // 1분마다 체크
```

**자동 재개 로직:**
```
// 예산 충전 시 자동 재개
IF 거래처_지갑_충전_이벤트:
    FOR 각 캠페인 IN 거래처.일시중지_캠페인들:
        IF 캠페인.일일_지출액 < 캠페인.일일_한도:
            캠페인_상태 = "ACTIVE"
            랭킹_재갱신_트리거(캠페인.카테고리들)
```

## E. 데이터 설계

### 테이블 요약

**광고주:**
- 기본정보, 잔액

**캠페인:**
- 광고주, 영역, 상품, 입찰가, 일예산, 상태(ACTIVE/PAUSED/ENDED) 등

**로그 테이블:**
- **노출**: session, 영역, 상품, AD_RANK, CPC, 순위, 슬롯번호
- **클릭**: session, 영역, 상품, 클릭시간, CPC
- **주문**: session, 상품, 수량, 금액
- **잔액 변경**: 시간, 금액, 담당자

### 실시간 랭킹 관리 테이블

**캠페인 상태 테이블:**
```
캠페인_상태:
- 캠페인ID
- 상태 (ACTIVE/PAUSED/ENDED)
- 일일_지출액
- 일일_한도
- 마지막_상태변경_시간
- 상태변경_사유
```

**예산 모니터링 테이블:**
```
예산_모니터링:
- 거래처ID
- 지갑_잔액
- 마지막_충전_시간
- 마지막_차감_시간
- 알림_발송_여부
```

**랭킹 재갱신 이력 테이블:**
```
랭킹_재갱신_이력:
- 재갱신ID
- 카테고리ID
- 트리거_이벤트 (캠페인_추가/수정/삭제/예산_소진)
- 재갱신_시간
- 영향받은_광고_수
- 처리_상태
```

### 특이사항
- 가격/입찰가는 실시간 DB 접근 필요
- 주문 이력 = 클릭 이후 발생 건만 집계
- 전환 매출 분배 시 클릭 수 기준 가중 평균
- **AD_RANK 점수**: 매일 갱신되는 실시간 데이터
- **슬롯별 노출 비중**: 최근 90일 데이터 기준
- **캠페인 상태**: 실시간 모니터링 및 자동 변경
- **예산 관리**: 실시간 추적 및 자동 일시중지/재개

## G. 확장 요건

### 가격 실험
- 실험 키(`exp_key`), 실험군(`exp_var`) 기반 상품 코드 변환 필요
- 클릭/구매 로그에 실험 정보 태깅 필수

### 개인화
- **Lv1**: 클릭 recency, 노출 frequency 기반 retargeting
- **Lv2**: 유저별 AD_RANK 추정
- **Lv3**: 머신러닝 모델 확장 가능성 고려 (현재는 보류)

### AD_RANK 고도화
- **방어값 개선**: CTR 0인 경우 더 정교한 점수 부여
- **개인화 AD_RANK**: 사용자별 맞춤 AD_RANK 계산
- **실시간 최적화**: 실시간 성과 데이터 반영
- **슬롯 확장**: 10개 이상 슬롯 확장 지원
