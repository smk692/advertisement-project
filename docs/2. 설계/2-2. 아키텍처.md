# AD_RANK 광고 시스템 아키텍처 (최적화)

## 📋 시스템 개요

**최적화 목표**: 
- **API 응답**: O(1) 조회 1-3ms, 엘라스틱서치 기반 병렬 처리
- **처리량**: 5000 RPS 이상 (병렬 처리로 대폭 향상)
- **정확성**: 정확한 잔액 차감 및 24시간 클릭-전환 매칭
- **비용 효율성**: **Flink 3개 Statement + Worker + 엘라스틱서치** 조합으로 최적 성능 달성

**핵심 컴포넌트**:
- **AD_RANK 엔진**: **광고 API 서버 + Worker + Flink + 엘라스틱서치** 조합으로 구성
  - **광고 API 서버**: 엘라스틱서치 O(1) 조회 중심의 초고속 응답
  - **Worker**: AD_RANK 계산 + 실시간 작업 (잔액 차감, 예산 모니터링, 캠페인 상태 관리)
  - **Flink**: 복잡한 스트림 처리 (성과 집계, 전환 매칭)
  - **엘라스틱서치**: O(1) 랭킹 조회, 병렬 처리 지원
- **Kafka**: 이벤트 스트리밍
- **Redis**: 실시간 상태 관리 및 캐시
- **Database**: 마스터 데이터 및 최종 저장소

## 🎯 핵심 데이터 플로우 (최적화)

### 1. 🚀 **AD_RANK 아키텍처 (엘라스틱서치 기반)**

#### **🔄 STEP 1: 사전 처리 (캠페인 등록/수정 - 승인 시)**

```mermaid
sequenceDiagram
    participant Admin as 어드민
    participant API as 광고 API 서버
    participant K as Kafka
    participant F as Flink AD_RANK Statement
    participant ES as 엘라스틱서치
    participant DB as Database
    
    Admin->>API: 캠페인 등록/수정
    API->>DB: 캠페인 정보 저장
    API->>K: campaign-events 토픽 발행
    API->>Admin: 즉시 응답
    
    Note over W: Worker: AD_RANK_CALCULATOR<br/>카테고리별 AD_RANK, CPC, 노출 순위, 노출 비중 계산
    K->>W: campaign-events 수신
    
    W->>DB: 카테고리별 활성 캠페인 조회 (JOIN)
    
    Note over W: AD_RANK 계산 시스템
    W->>W: 각 캠페인별 최근 1주일 데이터 수집<br/>노출수, 클릭수, 전환수 집계
    
    alt 데이터 충분 (클릭전환율 > 0)
        W->>W: 실제 클릭전환율 사용<br/>클릭전환율 = 전환수/클릭수
        W->>W: AD_RANK = 최대입찰가 × 클릭전환율(%)
    else 데이터 부족 (클릭전환율 = 0)  
        W->>W: 방어값 적용 (0.1% 기본값)<br/>클릭전환율 = 0.1%
        W->>W: AD_RANK = 최대입찰가 × 0.1%
    end
    
    W->>W: CPC 계산: (바로 아래 상품의 AD_RANK / 본 상품의 클릭 전환율(%)) + 1원
    W->>W: 노출 순위 계산: AD_RANK + 노출 기준치 가산점 + 구매 전환 가산점
    W->>W: 노출 비중 계산: AD_RANK 점수 / 전체 AD_RANK 점수 합계 (30% 상한 제한)
    W->>ES: 엘라스틱서치 인덱스 업데이트<br/>카테고리별 랭킹 데이터 저장
    W->>ES: 검색어별 랭킹 인덱스 업데이트
    W->>ES: 슬롯별 노출 비중 인덱스 업데이트
```

#### **🎯 AD_RANK 계산 시스템 세부 플로우**

**목적**: 카테고리별 AD_RANK 점수, CPC, 노출 순위, 노출 비중을 실시간으로 계산

```mermaid
graph TB
    Start([캠페인 AD_RANK 계산 시작]) --> DataCheck{클릭전환율 체크}
    
    subgraph "데이터 수집 (최근 1주일)"
        DataCheck --> |각 캠페인별| Collect["성과 데이터 수집<br/>- 노출수 (Impressions)<br/>- 클릭수 (Clicks)<br/>- 전환수 (Conversions)"]
    end
    
    subgraph "클릭전환율 계산"
        Collect --> CheckCVR{클릭전환율 > 0?}
        CheckCVR --> |Yes| RealCVR[실제 클릭전환율 사용]
        CheckCVR --> |No| DefenseCVR[방어값 적용 (0.1%)]
    end
    
    subgraph "AD_RANK 계산"
        RealCVR --> CalcADRank["AD_RANK 계산<br/>AD_RANK = 최대입찰가 × 클릭전환율(%)"]
        DefenseCVR --> CalcADRank
    end
    
    subgraph "CPC 계산"
        CalcADRank --> SortRank["AD_RANK 내림차순 정렬"]
        SortRank --> CalcCPC["CPC 계산<br/>CPC = (바로 아래 상품의 AD_RANK / 본 상품의 클릭 전환율(%)) + 1원"]
    end
    
    subgraph "노출 순위 계산"
        CalcCPC --> ExposureCheck["노출 기준치 체크<br/>노출수 ≥ 1,000회?"]

        ConversionCheck --> FinalRank["최종 노출 순위<br/>AD_RANK + 노출 기준치 가산점 + 구매 전환 가산점"]
    end
    
    subgraph "노출 비중 계산"

        WeightLimit --> Redistribute["초과분 재분배<br/>하위 랭크 상품들에 재분배"]
    end
    
    subgraph "엘라스틱서치 저장"
        Redistribute --> ESUpdate["엘라스틱서치 인덱스 업데이트<br/>카테고리별 랭킹 인덱스<br/>검색어별 랭킹 인덱스<br/>슬롯별 노출 비중 인덱스"]
    end
    
    ESUpdate --> End([AD_RANK 계산 완료])
```

**🔧 AD_RANK 파라미터 설정**

| 파라미터 | 기본값 | 설명 | 비고 |
|----------|--------|------|------|
| **데이터 수집 기간** | 1주일 | 클릭전환율 계산 기준 | 최근 성과 기준 |
| **방어값** | 0.1% | 클릭전환율 0인 경우 | 신규 캠페인 보호 |
| **노출 기준치** | 1,000회 | 노출 기준치 가산점 기준 | 통계적 유의성 확보 |
| **구매 전환 기준** | 1회 | 1,000회 노출 동안 구매 기준 | 전환 성과 기준 |
| **노출 비중 상한** | 30% | 단일 상품 최대 노출 비중 | 다양성 보장 |

**🎯 AD_RANK 적용 시나리오**

1. **신규 캠페인**: 클릭전환율 0 → 0.1% 방어값 사용
2. **저성과 캠페인**: 클릭 부족 → 방어값 적용
3. **정상 캠페인**: 충분한 데이터 → 실제 클릭전환율 사용
4. **예산 소진**: 캠페인 일시중지 → 랭킹에서 제외

### 2. 🔄 **최적화된 스트림 처리 (역할 분담)**

```mermaid
sequenceDiagram
    participant K1 as campaign-events
    participant K2 as ad-events  
    participant K3 as order.completed
    participant F as Flink (복잡한 작업)
    participant W as Worker (간단한 작업)
    participant ES as 엘라스틱서치
    participant DB as Database
    
    Note over F,W: AD_RANK 엔진 내부 역할 분담: 복잡한 작업은 Flink, 간단한 작업은 Worker, O(1) 조회는 엘라스틱서치
    
    par Worker: AD_RANK 계산 (복잡)
        K1->>W: 캠페인 변경 이벤트
        W->>W: 카테고리별 AD_RANK, CPC, 노출 순위, 노출 비중 계산
        W->>ES: 엘라스틱서치 인덱스 업데이트
    and Flink Statement 1: 성과 집계 (복잡)
        K2->>F: 클릭/노출 이벤트
        F->>F: 5분 WINDOW + 클릭전환율 계산
        F->>ES: 엘라스틱서치 성과 데이터 업데이트
    and Flink Statement 2: 전환 매칭 (복잡)
        K3->>F: 전환 이벤트  
        K2->>F: 클릭 이벤트 (24시간 보관)
        F->>F: 24시간 WINDOW + 클릭-전환 JOIN<br/>원본 상품코드 기준 기여도 계산
        F->>DB: 전환 결과 저장
    and Worker 작업 1: 실시간 잔액 차감 (간단)
        K2->>W: 클릭 이벤트 (CLICK만 필터링)
        W->>W: 즉시 차감<br/>CPC × 1회 차감
        W->>DB: ad_balance_histories INSERT
    and Worker 작업 2: 예산 모니터링 (간단)
        W->>W: daily_budget 카운터 체크
        W->>W: 90% 경고, 100% 자동 중지
        W->>DB: 캠페인 상태 변경
    and Worker 작업 3: 캠페인 상태 관리 (간단)
        K2->>W: 예산 소진 이벤트
        W->>W: 캠페인 일시중지 처리
        W->>ES: 랭킹에서 제외 처리
    end
```

### 3. 📊 **최적화 결과 비교**
